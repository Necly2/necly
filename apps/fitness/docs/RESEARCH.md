# Исследование источников данных

> Цель: понять, откуда фитнес-приложения берут базу упражнений и базу продуктов,
> и выбрать **бесплатные открытые** источники для личного учебного приложения.
>
> ⚠️ Часть сведений ниже — заявления вендоров и вторичные источники. Где я не уверен,
> это помечено. Перед тем как полагаться на лицензию — **проверь первоисточник сам**.

Дата исследования: 2026-11-15.

---

## 1. База упражнений — откуда она у всех

### Короткий ответ
Многие открытые фитнес-приложения берут упражнения из проекта **wger** (wger.de).
Мы это увидели напрямую: в исходниках Feeel таблица упражнений имеет поле `wgerId`,
то есть каждое упражнение ссылается на запись в базе wger.

### Что такое wger
- Open-source менеджер тренировок/веса на Django.
- **Код** под лицензией **AGPL-3.0-or-later**.
- **Данные упражнений** лицензией кода НЕ покрываются. По вторичным источникам
  исходные упражнения и ингредиенты дополнительно лежат под одной из лицензий
  **Creative Commons** (сторонний скрейпер указывает **CC-BY-SA 4.0**).
  🔸 *Не уверен на 100% — проверь на самой странице упражнения на wger.de перед использованием.*
  Практический смысл CC-BY-SA: можно использовать, но нужно **указывать авторство**
  и распространять производные под той же лицензией.

### Публичный REST API (ключевое для нас)
Читать публичные упражнения можно **без авторизации**. Токен нужен только для
данных конкретного пользователя.

| Что | Endpoint |
|-----|----------|
| Список упражнений | `GET https://wger.de/api/v2/exercise/` |
| Полная инфа (мышцы, оборудование и т.д.) | `GET https://wger.de/api/v2/exerciseinfo/<id>/` |
| Справочник мышц | `GET https://wger.de/api/v2/muscle/` |
| Справочник оборудования | `GET https://wger.de/api/v2/equipment/` |

Фильтры: по языку (`?language=...`), по мышце и др.

> 🔸 Просьба мейнтейнеров: если планируешь генерировать клиент из их API —
> сначала написать им. API помечен как «новый, может меняться».

### Как получить данные себе
- **Вариант A (онлайн):** дёргать API на лету и кэшировать в локальную SQLite.
- **Вариант B (офлайн-first, как Feeel):** один раз скачать нужные упражнения через API,
  сохранить как JSON в ассеты приложения, при первом запуске загрузить в локальную БД.
  **Рекомендую B** — приложение работает без интернета, как и задумано.
- Официального «кнопкой выгрузить всё» я не нашёл. Есть сторонние скрейперы (Apify),
  но надёжнее и честнее — пройтись по официальному API самому.

### Важно про контент
Анимации/картинки упражнений у Lyfta и Feeel — **их собственные** (Feeel рисует
low-poly из фото контрибьюторов). **Не копируй чужие картинки.** Варианты для тебя:
- брать изображения из wger (под их CC-лицензией, с указанием авторства), или
- свои фото/рисунки, или
- текстовые описания без картинок для MVP.

## 2. База продуктов для сканирования штрих-кодов

### Твоя проблема
Ты сканируешь штрих-код в одной стране — продукт не находится.
В **FatSecret** продукт твоей страны находится. Почему?

### Почему так происходит
- **FatSecret** — коммерческий сервис с **региональными коммерческими датасетами**
  (по их маркетингу — «90%+ мирового покрытия штрих-кодов» и «56+ локальных наборов данных»).
  🔸 *Цифра 90% — их собственное заявление, независимо не подтверждено.* Доступ к API —
  платный/проприетарный, с тарифами; региональные данные открываются на старших тарифах.
- **Open Food Facts (OFF)** — открытая, бесплатная, волонтёрская база (как «Википедия еды»).
  Покрытие **неравномерное по регионам**: отлично во Франции/Западной Европе,
  хорошо в Северной Америке, **хуже в остальных регионах**. То есть твоего продукта
  может просто не быть в базе в конкретной стране.

**Вывод:** дело не в «регионе API», а в том, **есть ли вообще продукт в базе**.
FatSecret находит, потому что покупает региональные каталоги. OFF — бесплатный, но
местами с пробелами.

### Open Food Facts API (бесплатно, без ключа)
- Lookup по штрих-коду (v2):
  `GET https://world.openfoodfacts.org/api/v2/product/<barcode>.json`
- Проверено вживую (2026-11-15): штрих-код `737628064502` → возвращает
  `product_name`, `brands`, `nutriments` (в т.ч. `energy-kcal`, `carbohydrates`,
  `proteins`, `fat`), `countries_tags`. HTTP 200.
- **Ключ не нужен.** Нужен корректный `User-Agent` (название твоего приложения +
  контакт), иначе могут троттлить. Иногда отвечает **HTTP 503** без закономерности —
  нужна обработка ретраев.
- Страновые поддомены (`us.`, `ru.`, `fr.` …) — это **языковые/страновые витрины
  одной и той же глобальной базы**, а не отдельные базы. Lookup по штрих-коду
  глобальный: если продукта нет в базе — он не найдётся ни на каком поддомене.
- Лицензия данных OFF — **Open Database License (ODbL)** (свободная, с требованием
  делиться производными базами данных на тех же условиях).

### Как решить проблему регионов в своём приложении
Стратегия **нескольких источников с fallback** (цепочка):
1. Спросить **Open Food Facts** (бесплатно, глобально, силён в ЕС).
2. Если не найдено — спросить резервный источник:
   - **USDA FoodData Central** (США, бесплатный API по ключу) — хорош для США;
   - при желании позже — коммерческий (FatSecret/Nutritionix) как последний резерв.
3. Если нигде нет — дать пользователю **добавить продукт вручную** (и, по-хорошему,
   закоммитить его обратно в OFF, чтобы база росла — именно так OFF и наполняется).

> 🔸 Численные сравнения размеров баз (OFF ~3 млн, FatSecret ~2 млн записей) взяты из
> вендор-аффилированного блога — относись к ним с осторожностью. Единственный надёжный
> способ выбрать источник — **прогнать десяток штрих-кодов из ТВОИХ магазинов через оба API**.

## 3. Итоговые решения для приложения

| Вопрос | Решение | Почему |
|--------|---------|--------|
| Упражнения | **wger API** → кэш в локальную SQLite | бесплатно, открыто, с мышцами/оборудованием |
| Хранение упражнений | офлайн-first (ассеты + БД) | работает без сети, как Feeel |
| Картинки упражнений | wger (с атрибуцией) или свои | нельзя копировать контент Lyfta |
| Продукты/штрих-коды | **Open Food Facts** (primary) + fallback | бесплатно, без ключа, силён в ЕС |
| Проблема регионов | цепочка источников + ручное добавление | OFF местами неполон |
