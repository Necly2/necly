# Архитектура приложения

Личное учебное фитнес + питание приложение. Flutter, офлайн-first, без подписок.
Вдохновлено Lyfta/Feeel, но весь код и данные — свои/из открытых источников.

## Принципы
1. **Офлайн-first** — всё хранится локально в SQLite (как Feeel). Сеть нужна только
   для подтягивания новых упражнений (wger) и поиска продуктов (Open Food Facts).
2. **Без платных фич** — нагрузка по мышцам, импорт/экспорт — всё бесплатно.
3. **Открытость данных** — экспорт в CSV в любой момент (твои данные — твои).
4. **Один дом для всего** — тренировки и питание в одном приложении.

## Стек
| Слой | Выбор | Причина |
|------|-------|---------|
| UI / фреймворк | **Flutter** (Dart) | один код на iOS+Android, трудно реверсить |
| Локальная БД | **drift** (ORM над SQLite) | типобезопасно, миграции, как у Feeel |
| Состояние | **Riverpod** | простое, тестируемое |
| HTTP | **dio** или `http` | запросы к wger / Open Food Facts |
| Сканер ШК | **mobile_scanner** | камера → штрих-код |
| CSV | **csv** | импорт/экспорт |

## Схема данных (ядро)
```
exercises(id, wger_id?, name, category, image_slug?, animated)
exercise_muscles(exercise_id, muscle, role)      -- какие мышцы и как
exercise_equipment(exercise_id, equipment)
workouts(id, name, category)                      -- шаблон тренировки
workout_exercises(workout_id, exercise_id, order, target_duration?, target_reps?)
workout_records(id, workout_id?, started_at, ended_at?, source)  -- факт: что сделал
set_records(id, workout_record_id, exercise_id, reps?, weight?, duration?, order) -- как сделал
foods(id, barcode?, name, brand?, kcal_100g, protein_100g, carbs_100g, fat_100g, source)
nutrition_logs(id, food_id, logged_at, grams)     -- что съел
```
Ключевое отличие от Feeel: `workout_records` + `set_records` фиксируют **факт
выполнения** (что и как сделал по подходам), а не только шаблон. Это и есть
«выгрузка каждой тренировки», которую ты хочешь.

## 🔑 Фича «нагрузка на группу мышц» (бесплатно)
Lyfta берёт за это деньги. Логика проста и считается из уже имеющихся данных:

1. Каждое упражнение связано с мышцами (`exercise_muscles`) с ролью
   (основная/вспомогательная) — данные из wger.
2. Мышцы группируются в группы (грудь, спина, ноги, плечи, руки, кор…).
3. За период берём все `set_records`, для каждого — упражнение → его мышцы.
4. Считаем «очки нагрузки»: основная мышца = вес 1.0, вспомогательная = 0.5
   (коэффициенты настраиваемы). Умножаем на объём (подходы × повторы или время).
5. Суммируем по группам → получаем распределение нагрузки (для диаграммы).

Алгоритм — в `features/muscle_load/muscle_load_service.dart`, покрыт тестом.

## Импорт из Lyfta / других приложений
Единый путь — **CSV**. Пользователь экспортирует историю из Lyfta (или другого
приложения) в CSV, приложение парсит и создаёт `workout_records` + `set_records`.
Парсер сделан гибким (маппинг колонок), т.к. формат у каждого приложения свой.
🔸 Точный формат выгрузки Lyfta мне неизвестен — маппинг колонок настраиваемый,
а тестовый образец формата надо будет снять с реальной выгрузки.

## Питание и штрих-коды
- Сканер (`mobile_scanner`) → штрих-код → `FoodLookupService`.
- `FoodLookupService` идёт по цепочке источников (Open Food Facts → fallback →
  ручной ввод), см. RESEARCH.md.
- Найденный продукт сохраняется в `foods`, запись приёма — в `nutrition_logs`.

## Экспорт для анализа в Claude
Кнопка «Экспорт в CSV» выгружает два файла: `workouts.csv` и `nutrition.csv`.
Их можно вставить в другой проект Claude — он проанализирует тренировки и питание
вместе. Формат экспорта — простой плоский CSV (см. `csv_service.dart`).
